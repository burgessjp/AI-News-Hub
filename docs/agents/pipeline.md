# 数据流水线（scripts/）与 CI/CD

> 面向 AI 编码代理的领域约定，从根 `AGENTS.md` 拆出。动 `scripts/` 下脚本、流水线行为、GitHub Actions 前先读本文。

## 流水线

`pipeline.sh` 是唯一编排入口（CI 与本地都调它）。缺这 4 个环境变量之一直接 `exit 1`：

```
AI_NEWS_HUB_AI_BASE_URL / AI_NEWS_HUB_AI_MODEL / AI_NEWS_HUB_AI_API_KEY / GITCODE_TOKEN
```

- 抓 8 源（7 个第三方站点 + `aihot.virxact.com` 精选 `/items?mode=selected&take=20`）→ 各源 AI 摘要（`ai_summary.py`，写入快照顶层 `ai_summary_v2`，每项含 `title`+`desc`+`url`，url 由 AI 返回的条目编号回填）+ 跨源总览（`overview_summary.py`，写入 `index.json` 顶层 `latest_overview`，含 `digest` 综述 + items；生成成功时**同步落盘 `overview/<date>/<HH-MM>-data.json` 按日归档**，保留 90 天——与快照的 31 天刻意不同档，总览是唯一覆盖即失的 AI 产物，归档即其历史）→ 推送到 gitcode 数据仓库 `peng1818/AI-News-Hub-Data` 的 `news-hub-data` 分支；push 阶段 overlay 后由 `trend_keywords.py` 扫近 14 天历史快照做词频统计（**统计为主 + 每批至多一次 AI 精修**），写根级独立文件 `trends.json`（整文件覆盖，失败只告警不阻断推送、下次自愈；统计部分可全量重算，AI 精修失败的批次退回统计回退榜，均无继承语义）＋ 根级独立文件 `trends_cloud.json`（趋势词云候选：同批同口径的纯统计 top ~60 轻量词条（term/display/total，护栏词优先），AI 精修不触碰、不进按日归档，写入失败仅告警不影响热词榜），并**同步落盘 `trends/<date>/<HH-MM>-data.json` 按日归档**（索引 `trends_history.json`，90 天指针，对齐总览归档档位；归档/索引失败仅告警，根级 `trends.json` 已写仍算成功）＋ 依据「昨日最后一期」归档为每个热词附上排名变化字段 `rankChange` / `isNewEntry`（App 显示 +N/-N/持平/新上榜；基准必须在写今日归档前取，否则会把今日早批当基准；无历史基准时整个字段不输出）。
- **语音速报预生成音频**（`tts_broadcast.py`，插在 fetch 与 push 之间）：按当日 `latest_overview` 的**综述 digest**（仅综述，不含 Top10 条目明细；文本 = digest.trim()，与 App 端兜底朗读文本一致，两侧必须同步）用 Qwen3-TTS（Qwen3-TTS-12Hz-0.6B-CustomVoice，Apache-2.0，音色 serena，文本规范化内建）经 qwentts.cpp（MIT，GGML C++17，纯 CPU 无 Python ML 依赖）合成为**单段 MP3**（综述百字级，单次合成远低于引擎 2048 帧上限，无需分段拼接；单声道 24kHz 48kbps，`out/audio/<date>/broadcast.mp3` 固定文件名同日覆盖，固定 `--seed` 保证同日重跑产物稳定），描述写入 index.json 顶层 `latest_audio`（扁平字段 file/title/durationMs/bytes；`generatedAt` 对齐 `latest_overview.generatedAt`，App 据此判定新鲜度；总览继承批次照常生成，音频对齐旧 generatedAt）。**任何失败只告警不抛非零**（引擎构建失败/模型下载失败/overview 缺失/综述合成**重试 1 次后**仍失败/阶段墙钟预算耗尽/整阶段异常；预算默认 1200s 覆盖自举+合成，`AI_NEWS_HUB_TTS_BUDGET_S` 覆盖、0 = 不限——TTS 在 push 之前执行，预算把阶段墙钟钉死在上限，任何 hang/慢批次都拦不住其后的推送），合成成功才写清单（失败当批不写）→ App 回落系统 TTS，下批自愈。资产全部动态获取（git 浅拉 pin SHA + ggml 子模块 + cmake 构建 + curl 下 GGUF ≈1.2GB Q8_0 两件套，HF 主源 + hf-mirror 兜底，`third_party/` 不入库，二进制/GGUF 按文件级判在位、缺啥补啥；GGUF 判在位含 magic 头 + 字节下限完整性校验，缓存残卷/假成功下载会被删除重下，不会天天失败不自愈）；env：`QWENTTS_DIR` 指向已有检出、`QWENTTS_MODELS_DIR` 指向已有 GGUF 目录、`QWENTTS_REF` 覆盖 pin（升级改它 + 脚本 `DEFAULT_QWENTTS_REF` + workflow env 三处同步）、`QWENTTS_HF_HOST` 覆盖下载源、`AI_NEWS_HUB_TTS_VOICE` 换音色（serena/vivian/uncle_fu/dylan 北京话/eric 四川话等 CustomVoice 预置）、`AI_NEWS_HUB_TTS_BUDGET_S` 覆盖阶段墙钟预算（默认 1200s，0 = 不限）、`AI_NEWS_HUB_TTS_DISABLE=1` 整体跳过；`audio/` 目录 14 天滚动清理由 `push_data.py` 在 overlay 后显式做（overlay 只增不删）。
- **趋势榜单规则**（`trend_keywords.py`）：入榜门槛不变（窗口期 `total ≥ 3` 且 `daysActive ≥ 2`）；排序按**动量加权分**（近 7 日命中和 × min(动量比, 2.5)，动量比 = (近3日+1)/(前3日+1)——纯 total 排序是热度榜，常青词常年霸榜头部固化）；非别名归一的**自由 unigram 不直接入榜**（拆词残留 work/long 之类只能活在 bigram 里或经 AI 捞回，按分值序补位到满 10 个，榜单长度恒定）；`trend` 带 ±max(1, 前3日×15%) 容差带（无容差时 101 vs 100 也标 up，箭头近似噪声）；**AI 精修**每批把候选池（按分值序 top 25，宽口径含被护栏拦下的词）喂给 LLM 合并同话题候选 / 剔除泛词 / 规范 display（可为中文），选不满 10 个时按分值序用统计候选补齐，配置缺失、调用失败、校验不过一律零降级回退统计回退榜，不告警不阻断；排序语义切换后的首批 `rankChange` 会有一次性全榜跳变（归档是成品快照，不受影响）。
- **趋势抽词规则**（`trend_keywords.py` 的 `_extract_terms`，2026-08 词面质量收紧）：英文 unigram + 相邻 bigram；所有格 `'s` 分词前剥掉（防 `builder's` 切出 `s` 残片）；**自由 token 须 ≥2 字符且含字母**——纯数字/小数 token（`3`、`3.7`）只允许活在别名变体里（如 `gpt 5`），自由组合会配出 `7 flash`、`2 4t` 碎片；**自由 bigram 两侧均须非停用词且间隔只允许空格/Tab 或恰好一个连字符**——换行、逗号句号、CJK 字符一概不配对（多字段拼接边界与跨标点都是假相邻，曾拼出 `flash google`、`questions about` 类噪声；`long-horizon` 式连写复合词要保），别名变体对不受任何约束（`open-source` 连写形式靠它命中）；因此 `_item_fields` 多字段拼接一律用换行而非空格；**带版本号的模型名（GPT-5.6 Sol / DeepSeek V4 / Grok 4.5 / Qwen3.8 等）必须在 `ALIASES` 登记才能入榜**，数字侧 token 过不了字母约束；停用词缺口按词云实锤垃圾词滚动补（补词前先核对不会误杀在榜好词，如 `long`/`report`/`research` 故意不加）。
- **历史索引与趋势拆在根级独立文件**：`history.json`（摘要历史，每源 31 天）与 `overview_history.json`（总览归档，90 天）由 `build_history` / `build_overview_history` 写出，`trends.json` 与 `trends_history.json` 由 `write_trends` 写出，**均不进 index.json**（index 只保留即时字段 updated_at / latest / latest_overview / latest_audio，体量有界）。`load_previous_index` 只拉前三个文件（fetch 阶段合并基线）；`trends_history.json` 不走它——push 阶段 clone 里就有全量历史，`write_trends` 直接从 checkout 读。独立文件优先；404 时回退 index 内联字段（拆分上线的过渡迁移，一次即完成）；无内联但仓库已有历史数据（文件意外丢失）→ fail-closed `exit 1`，宁可本轮不更新也不推塌缩索引。
- 单源失败跳过且 `index.json` latest 指针从上一次继承（客户端永远拿到有效数据）；总览 AI 生成失败时 `latest_overview` 同样继承上一次，当日归档不落盘（`overview_history.json` 从上一次索引继承，当天早批次的归档仍可寻址）。≥1 源成功退出码即为 0。日期统一北京时间。
- `backfill_overview.py` 为一次性运维脚本：从数据仓库 git 历史提取旧版 index.json 里的 `latest_overview` 回填成 `overview/` 归档文件 + 重建 `overview_history.json` + 清理已下线源遗留目录（含 `--dry-run` 核对清单）；回填一次即完成，日常流水线自动接力，勿重复跑。`backfill_trends.py` 同为一次性运维脚本（从 git 历史提取各期 `trends.json`／拆分前 index.json 内联 `latest_trends`，回填 `trends/` 归档 + 重建 `trends_history.json`；一律完整重克隆 `repo/` 后自写自推，需 `GITCODE_TOKEN`）。`backfill_history.py` 同为运维脚本（重建 `history.json` / `--prune` 删起始日前目录）。
- **Product Hunt `postedAfter` 恒用 PT（太平洋时间）当日 0 点（带时区偏移，`scripts/sources/producthunt.py` 的 `_ph_today_pt_start()`），勿改回 UTC 边界**：PH 把每个帖子的 `createdAt` 规范化到上线日 PT 00:01（夏令时 = UTC 07:01、冬令时 = UTC 08:01）且「Product of the Day」按 PT 自然日排榜；用 UTC 当日 0 点过滤，北京 08:00 批（= UTC 00:00 整）会把当前榜单整体过滤成空、误报「源站改版」；冬令时下贴近 UTC 07:01 边界抓取同样会拿空（本仓库 22:00 批 = UTC 14:00，距边界已远，无此风险）。
- **抓取器按源拆在 `scripts/sources/` 包**（2026-08-29 起，对齐 App 端 `data/source/` 形态）：每源一个模块（`hackernews.py` … `openai_anthropic_news.py`，含各自的私有辅助与 items 字段 docstring）、`httpio.py` 是全部 HTTP 的唯一咽喉（UA/SESSION/超时/CF 检测）、`__init__.py` 组装注册表 `SOURCES`（**顺序承重**：= main 串行抓取序 = index latest 键序 = history 键序，与 `common.SOURCE_KEYS` 展示序刻意不同，`test_sources_registry.py` 钉死）并写明抓取器契约与**新增数据源全链路 checklist**（新增源必读）。`fetch_data.py` 只保留编排（fetch_with_retry / main）与归档/索引层（write_snapshot / write_index / load_previous_index 等，backfill 脚本 import 的符号全在此层，未随拆分移动）。
- 数据格式详见 `docs/news-hub-data-usage.md`；各脚本行为见脚本头注释。
- **测试**（pytest，`scripts/tests/`，规约详见 docs/agents/testing.md 的 Python 小节）：`fetch_data.py` 的失败继承语义（单源失败 latest 指针继承、总览失败 latest_overview 继承、≥1 源成功退出码 0、全部失败退出码 1 但本地 index 照写由下游 `set -e` 拦推送、上一索引拉取失败与历史独立文件丢失的 fail-closed `exit 1`、`--only` 与空结果豁免源行为）已全部钉成回归测试——**动 `fetch_data.py` 或 `scripts/sources/` 前先跑 `scripts/.venv/bin/python -m pytest scripts`**；`write_index` 的 `results` 形参当前未被使用也被显式钉死，改用 results 驱动继承必须是有意识决策。CI 在 `build.yml` 的 `pipeline-tests` job（push/PR 触发）——**刻意不在 `fetch-data.yml` 每日批里跑**：批跑的是 main HEAD（push 时已测过），测试失败不该 forfeiture 当天数据推送。

## CI/CD

`.github/workflows/`：`build.yml`（PR 跑 `assembleDebug` + 并行 `pipeline-tests` job 跑流水线 pytest）/ `release.yml`（`v*` tag 发版，从 secrets 还原 keystore，versionName/versionCode 从 tag 注入）/ `fetch-data.yml`（每日定时跑数据流水线；语音速报**零 Python 依赖**——引擎克隆/cmake 构建/GGUF 下载全由 `tts_broadcast.py` 按需自举，`actions/cache` 缓存整个 `third_party/tts-engine`（源码 + build 二进制 + ≈1.2GB GGUF，key 绑 `QWENTTS_REF` pin SHA；脚本按二进制/GGUF 文件级判在位，缓存缺啥补啥，无目录级恢复陷阱）；timeout 50 分钟 = 25（抓取+AI+推送）+ TTS 阶段墙钟硬上限 20 + 冷缓存自举余量）。
